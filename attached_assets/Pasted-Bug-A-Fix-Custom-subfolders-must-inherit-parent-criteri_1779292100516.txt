Bug A Fix — Custom subfolders must inherit parent criteria folder context (HIGH PRIORITY)
Files uploaded into Drive-created subfolders (like "Peer Reviews" and "Events" inside "Judge of Others' Work") have folderType: 'custom' and are silently dropped before reaching Claude.
Fix in driveDocumentFetcher.ts — extend the grouping logic to walk custom subfolders and attribute their documents to the parent criteria folder:
typescript// Build a lookup map: custom folder id → parent criteria folder
const customFolderParentMap = new Map<number, { criteriaName: string; folderType: string }>();

for (const folder of folders) {
  if (folder.folderType === 'custom' && folder.parentFolderId) {
    // Find the parent folder
    const parent = folders.find(f => f.id === folder.parentFolderId);
    if (parent) {
      if (parent.folderType === 'criteria') {
        // Direct child of a criteria folder
        customFolderParentMap.set(folder.id, {
          criteriaName: parent.name,
          folderType: 'criteria'
        });
      } else if (parent.folderType === 'custom') {
        // Nested custom subfolder — walk up to find the criteria ancestor
        let ancestor = parent;
        while (ancestor && ancestor.folderType === 'custom' && ancestor.parentFolderId) {
          ancestor = folders.find(f => f.id === ancestor.parentFolderId)!;
        }
        if (ancestor && ancestor.folderType === 'criteria') {
          customFolderParentMap.set(folder.id, {
            criteriaName: ancestor.name,
            folderType: 'criteria'
          });
        }
      } else if (parent.folderType === 'resume') {
        customFolderParentMap.set(folder.id, { criteriaName: '', folderType: 'resume' });
      } else if (parent.folderType === 'demographics') {
        customFolderParentMap.set(folder.id, { criteriaName: '', folderType: 'demographics' });
      }
    }
  }
}

Bug B Fix — Name mismatch safety (MEDIUM PRIORITY)
The lookup grouped.byCriteria[criteriaName] uses exact string match. If petition_criteria_exhibits.criteriaName differs from case_folders.name by even one character, the assessment silently returns INSUFFICIENT.
Fix in criteriaAssessmentService.ts:
typescript// Instead of exact match only, try normalized match as fallback
function findCriteriaDocuments(
  byCriteria: Record<string, FetchedDocument[]>,
  criteriaName: string
): FetchedDocument[] {
  // Try exact match first
  if (byCriteria[criteriaName]) return byCriteria[criteriaName];

  // Normalize: lowercase, remove apostrophes, trim whitespace
  const normalize = (s: string) => s.toLowerCase()
    .replace(/['']/g, "'")
    .replace(/\s+/g, ' ')
    .trim();

  const normalizedTarget = normalize(criteriaName);
  const matchingKey = Object.keys(byCriteria).find(
    key => normalize(key) === normalizedTarget
  );

  if (matchingKey) {
    logger.warn(
      { criteriaName, matchedKey: matchingKey },
      '[assessCriteria] criteria name fuzzy matched — check for data inconsistency'
    );
    return byCriteria[matchingKey];
  }

  return [];
}
Replace the current lookup:
typescript// Before
const criteriaDocuments = grouped.byCriteria[criteriaName] ?? [];

// After
const criteriaDocuments = findCriteriaDocuments(grouped.byCriteria, criteriaName);
Also add a warning log when the fuzzy match fires so data inconsistencies are visible in logs.
